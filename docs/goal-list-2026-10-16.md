# Atelier goal list

Oct 16, 2026 · @Thiago Fernandes

Implementation checklist for the supplied 16 October goal list. Checked boxes record source implementation; the verification section below records the tests and their limits.

## How to read this

There are 54 goals for making Atelier look and move better, grouped by surface, with six to start on first. Tick each one off as it ships.

Effort is a first estimate on TRIAGE.md's scale: Trivial (an afternoon) < Small < Medium < Large. Goals already on TODO.md say so, and goals that break a rule in DESIGN\_SYSTEM.md are marked so you can decide. Written against commit `1f7ad72`.

## Start here

These six change how Atelier looks the most for the least new code; each one builds on something the app already has.

1. **Hero banner header.** The cheapest large change to the library's look; the artwork is already cached.
2. **Filmic tone mapping and environment light.** Models in the viewport stop looking flat, for a few lines in `viewport.js`.
3. **Theme-matched window.** Removes the white launch flash and the light title bar in dark mode.
4. **Materialize on load.** A memorable first look at every model that reuses the loader's wireframe style.
5. **Directional folder transitions.** Gives the library a sense of place with one CSS animation.
6. **Operation toasts that resolve in place.** Brings every remaining spinner toast in line with the export and save animations.

## 3D viewport

The viewport is where the art is, so it gets the most polish; each animation plays once or on request, never idly.

- [x] **Filmic tone mapping** (Trivial). The renderer sets only `outputColorSpace` today. AgX or ACES Filmic tone mapping, both in the vendored three.js, keeps bright emissives and highlights from clipping to flat white.
- [x] **Environment light** (Small). A generated studio environment (three.js `RoomEnvironment` through PMREM) adds soft reflections and fill, so materials stop looking flat. Needs one more vendored jsm file.
- [x] **Lighting moods** (Small). Studio (today's rig), Rim-lit, Flat for true colours, and Emissive only, where the scene goes dark and only glow shows.
- [x] **Materialize on load** (Small). When geometry is ready, a wireframe pass sweeps into the shaded model over about 400 ms, once per open, using a clipping plane. It continues the loader's wireframe look; reduced motion shows the model at once.
- [x] **Colour tweens** (Small). Dye and emissive edits blend to the new colour over about 150 ms in linear space instead of snapping.
- [x] **Smooth camera** (Small). Reset view eases back instead of jumping, and double-clicking a part eases onto it. Builds on `frameCamera()`.
- [x] **Hover highlight** (Small). The part under the cursor gets a thin accent outline, and its material name shows in the corner.
- [x] **Better floor** (Small). Swap `GridHelper` for a grid that fades with distance, plus a soft contact shadow under the feet.
- [x] **Backdrops** (Small). A theme-tinted gradient, a plain colour, or a transparent checker.
- [x] **Bloom on emissives** (Medium). An optional glow pass behind a quality toggle, so glow looks closer to how it does in game. TODO.md already notes WebView2's GPU limits, so it stays off by default.
- [x] **Viewport frame** (Small; revised by the selected redesign). A distinct Model Studio boundary and small axis gizmo orient the stage. The later user-selected layout supersedes the floating corner brackets; loader brackets remain.

## Motion: navigation and continuity

These goals give the app a sense of place: you can tell which way you moved and where a panel came from.

- [x] **Directional folder transitions** (Small). Opening a folder fades the new grid in from 8 px to the right; Back brings it in from the left, in about 160 ms. It moves the grid container when it is replaced, never card layout, which DESIGN\_SYSTEM.md rules out.
- [x] **Card-to-editor morph** (Medium). The material, curve and VFX editors grow out of the clicked card and shrink back into it on close.
- [x] **Portrait to banner** (Medium). Opening a hero folder carries its portrait up into the hero banner header as one continuous move.
- [x] **Breadcrumb hand-off** (Small). The clicked folder's name slides into the breadcrumb trail.
- [x] **Dialog exits** (Trivial). Overlays fade in with `dialogIn` but vanish on close; give them a matching 120 ms exit.
- [x] **Context menu from the cursor** (Trivial). The menu scales from 0.96 to 1 out of the click point over 120 ms.

The View Transitions API covers the first four in WebView2; feature-detect it on Linux and fall back to plain CSS.

## Motion: feedback and progress

Every one of these follows a real result, the same rule the six existing motion sets keep.

- [x] **Operation toasts that resolve in place** (Medium). "Replacing…", "Resetting…", "Packing…" and "Preparing for Blender…" turn into their own success, warning or error state instead of being swapped for a new toast. Use the same mount and setState handle as export feedback and material save.
- [x] **Collated toasts** (Small). Repeats merge into one toast with a ×2, ×3 counter that bumps and resets the timeout. On TODO.md.
- [x] **Toast timer line** (Small). A hairline along the bottom shows time until dismissal; it already pauses on hover.
- [x] **Fly to Edited Assets** (Small). After a confirmed save or import, the thumbnail's ghost arcs into the sidebar and the count bumps.
- [x] **Rolling counters** (Small). Selection, library and Activity counts roll their digits instead of jumping.
- [x] **Row exits** (Small). Removing an Edited Assets row collapses and fades it instead of making it vanish.
- [x] **Swatch change wipe** (Small). On Use value, Revert unsaved or a paste, the swatch wipes from the old colour to the new over 120 ms. Extends the existing `matflash` highlight.
- [x] **Thumbnail skeletons and swap** (Small). A shimmer placeholder only while a preview loads, then a crossfade; a replaced texture's preview wipes from old to new.
- [x] **Segmented import progress** (Small). Replace "Downloading 3 / 12 assets…" with one segment per asset that fills as each finishes, failed ones marked.
- [x] **Activity ring** (Small). A ring and count pip on the Activity button while jobs run; it turns determinate when a job reports progress.
- [x] **Packing animation** (Small). Edited Assets rows fold into the existing tray graphic when export starts, then the real export feedback takes over. It never delays input.

## Look: surfaces and identity

These give Atelier a recognisable face using artwork and colours it already has.

- [x] **Hero banner header** (Small). Inside a hero or skin folder, the library header shows that artwork faded into the surface on the right. The catalogue already caches it.
- [x] **Hero roster home** (Medium). A portrait strip with each hero's skins beneath, using the 54 portraits and 690 skin artworks already catalogued.
- [x] **Category accent line** (Trivial). The header rule takes the folder's category colour from the 22 `--studio-icon-*` roles.
- [x] **Clipped corner means yours** (Small). Reuse the material-save cartridge's clipped corner as the edited marker on cards and sidebar rows: one shape for "your work" across the app.
- [x] **Type glyphs on asset tiles** (Small). A small corner glyph in the category colour, so mixed folders scan by type.
- [x] **Colour previews in Edited Assets** (Small). Textures already show their preview in the sidebar, but materials and curves show a generic symbol. Show a material's main colours as a small swatch mosaic, and a curve's sparkline, which the VFX editor already draws.
- [x] **Empty-state family** (Medium). The technical-tray illustration style for no search results, no projects, empty Activity and an offline catalogue.
- [x] **Material colour chips** (Small). Each material in the viewport's list shows its main colour.

## Look: themes, window and startup

The first second after launch and the frame around the app set the tone before anything else loads.

- [x] **No white flash on launch** (Small). `window.py` creates the window with no background colour. Pass the saved theme's surface colour; the theme lives in WebView storage, so Python needs a cached copy.
- [x] **Title bar matches the theme** (Small). On Windows, set the dark title bar through DWM and, on Windows 11, the caption colour, updated from JavaScript when the theme changes.
- [x] **Splash with real progress** (Medium). Replace the launch toast with a light splash: the A mark plus "Reading container 12 / 36" from the index walk. On TODO.md.
- [x] **Theme switch reveal** (Small). Changing mode or palette spreads the new theme outward in a circle from the control you clicked. Reduced motion swaps instantly.
- [x] **More palette presets** (Small). High contrast (already a follow-up in DESIGN\_SYSTEM.md), Blueprint (technical blue to match the wireframe motif) and Comic ink (paper, ink and one accent).
- [x] **Adaptive accent, opt-in** (Medium). Inside a skin's folder, take the accent from its artwork; `theme.js` already derives contrast-safe shades. Approved exception: DESIGN\_SYSTEM.md rules out colour extraction; update it to allow this opt-in case when it ships.
- [x] **Density setting** (Medium). Comfortable or Compact control heights and padding.

## Look: depth, type and detail

Small finishing details are what make an app feel crafted; most of these take an afternoon.

- [x] **Frosted dialog backdrops** (Trivial). Overlays blur the library behind them with `backdrop-filter`, which Atelier doesn't use yet, instead of only dimming it.
- [x] **Elevation scale** (Small). One `--studio-shadow` serves everything today; three levels for cards, menus and dialogs give surfaces depth.
- [x] **Condensed display titles** (Small). The bundled Roboto variable font has a width axis from 75 to 100, so page and dialog titles can go condensed and heavier with no new font.
- [x] **Themed scrollbars and selection** (Trivial). Thin scrollbars and text selection in the palette's colours.
- [x] **Glowing HDR swatches** (Small). A halo that grows with intensity, so a 9,9,9 emissive reads at a glance.
- [x] **Alpha checkerboard** (Trivial). Under swatches and transparent texture previews, so alpha is visible.
- [x] **Tabular numerals** (Trivial). Everywhere a number changes in place, so widths stay put; only a few spots use them today.
- [x] **Subtle grain** (Small). A very fine noise layer on dark backgrounds to soften flat fills; off in light mode.

## Delight (optional)

These are small rewards that make people fond of the app; each is easy to leave out.

- [x] **First export moment** (Small). One time only, after the first successful export: a short burst in the mod's own colours. Static under reduced motion.
- [x] **Logo replay** (Trivial). Clicking the A mark replays its 320 ms entrance.
- [x] **Skin-tinted loader** (Small). The viewport loader's brackets take the colour of the skin being opened, from its catalogue artwork.

## Ground rules

Every goal keeps the rules DESIGN\_SYSTEM.md and the motion README already set.

- Motion reports real state: no fake progress or simulated loops.
- Every animation has a static pose under reduced motion, from the OS or the forced setting.
- Nothing delays input or holds back a click.
- The original no-idle rule was superseded by the user's follow-up: play a compatible standing idle on repeat by default, with Pause and Rest pose controls.
- Engine differences between WebView2 and WebKitGTK, such as View Transitions, are feature-detected with a plain fallback.
- New motion sets use the shared mount, setState and destroy handle, and fall back to static artwork if a script fails.
- Each new set ships with a browser check and a native smoke check, like the existing six.

## Implementation and verification

The viewer completion adds smooth Fit and double-click framing, exact linear colour/texture display transitions, an accent outline, a fading shader grid and soft grounding shadow, theme/plain/transparent backdrops, opt-in emissive bloom and camera axes. Single click selects a material and reveals its inspector; Advanced parameters opens the existing full editor. Models open with one visible mesh, saved textures where present and original textures otherwise, and a compatible standing idle playing on repeat. Rim lighting and the game's opaque preview rim shell are omitted. Loading textures triggers a scan directly on the model until its appearance is ready.

Viewer display code: `gui/viewport-inspection.js`, `gui/viewport-effects.js`, `gui/viewport.css`. Navigation and presentation: `gui/continuity.js`, `gui/polish.js`, `gui/polish.css`. Themes and preferences: `gui/theme.js`, `gui/preferences.js`, `atelier/window_theme.py`. Hero artwork: `gui/roster.js`, `atelier/hero_artwork.py`. Backend S maps and saved previews: `atelier/s_maps.py`, `atelier/ui_preview.py`.

Browser checks in `tests/viewport_inspection_checks.py` exercise rendered geometry, shader compilation, exact final colours, texture transitions, camera focus, bloom pixels and cleanup, alpha captures, reduced motion, material editor return, real decoded geometry/standing idles, and poster/turntable restoration. `tests/polish_checks.py` and the combined browser suite exercise the other presentation goals. `tests/desktop_smoke.py --fixtures --interactions` runs viewer checks in native WebView2. `tests/frozen_smoke.py --viewer-checks` repeats them against the actual packaged app and verifies packaged viewer files match source.

This checkout includes and preserves the source changes found after the reset. The original OneDrive checkout rejected file creation, so implementation and verification use a separate local checkout. Windows tests do not establish Linux/WebKitGTK/Wine support or in-game shader/cloth/VFX fidelity. The soft floor shadow and bloom are optional display approximations, never game material edits.

Functional checkpoint verified: 19 backend suites pass (two native-only checks skipped in that isolated runner), 116 browser checks pass, 18 packaged WebView2 checks pass, and three live-game checks pass using the packaged native mesh/material/texture and standing-idle routes. No page or shader errors were reported. Reports: ../verification.json in the external build directory.

The user selected redesign option 1 and requested contextual editing controls plus a separate working environment. Model Studio implements that selection with a distinct header and local blue/slate surfaces, grouped materials, a part picker when needed, collapsed advanced controls, exclusive Model/View settings menus, one Save changes action and inline progress/results. Floating corner brackets were superseded by this selected design.
