# Material 3 foundation

Atelier remains a desktop creative application built with vanilla JavaScript, Bottle, Three.js and pywebview. This phase establishes shared visual rules and improves browsing without changing the asset pipeline, project format, native tool commands or mod container formats.

## Direction and sources

The default Atelier palette uses neutral charcoal surfaces, controlled blue primary actions and quiet grey-green secondary containers. Light mode uses cool near-white and grey surfaces with a deeper blue primary. Darcula adds warm orange accents, and Repak X uses near-black, dark grey and red. Distinct category hues remain visible as muted pigments. Errors and destructive actions keep dedicated semantic roles even when the chosen accent is red. The model stage offers a theme gradient, plain colour or transparent checker; interface styling never filters or recolors artwork.

This is a desktop adaptation of [Material 3 color roles](https://m3.material.io/styles/color/roles), [typography](https://m3.material.io/styles/typography/applying-type), [buttons](https://m3.material.io/components/buttons/overview), [motion](https://m3.material.io/styles/motion/overview/how-it-works) and Google's [Material 3 Expressive research](https://design.google/library/expressive-material-design-google-research). It adopts their hierarchy, containment, shape and purposeful motion principles while keeping desktop density. It is not a claim of full Material component or accessibility conformance.

## Theme and motion

Appearance lives in first-run configuration and Menu → Settings. The toolbar ends with Activity and Menu; it has no dedicated theme selector. The header logo and wordmark are black in Light and white in Dark, including the optional logo animation and its fallback.

Light, Dark and System are saved under the existing `atelier.theme` key. Atelier (stored as `studio` for compatibility), Darcula and Repak X display four adjacent color circles for background, surface, foreground and accent. Each preset has light/dark variants. The final + Custom button restores a custom draft or starts from the selected palette. Four native HTML color pickers edit its colors. Name and save up to 24 reusable custom palettes; each contains both light/dark variants and can be selected or deleted independently. Names render as literal text. Editing a saved palette starts a custom draft without overwriting it.

Background keeps the chosen value. Semantic text, supporting text, button foregrounds and accent shades are derived for at least 4.5:1 contrast against their surfaces. If requested text/surface colors conflict, text and surface shades adapt and Settings explains the adjustment; the original choices remain in the saved palette. Presets use the same semantic roles as custom themes. These are curated Material 3 role palettes; the four-color editor does not implement Android wallpaper extraction or HCT tonal palette generation.

Palette selection, custom drafts and named palettes use version 2 of `atelier.appearance` browser/WebView storage. The reader accepts version 1 and validates stored colors, names and IDs. Appearance applies immediately, independently of the Settings path Save/Cancel buttons. It never writes Python configuration or project metadata. The preference is applied before CSS to avoid an opposite-theme flash, follows OS changes in System and synchronizes other windows through storage events. Malformed or unavailable storage falls back safely. Browser mode and the desktop profile have separate preferences.

Global select/option/optgroup roles theme filters and editors as well as Settings. Supporting engines progressively opt into [customizable native selects](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/Customizable_select) using `appearance: base-select` and `::picker(select)`: popup surfaces, checkmarks, selected, hover and keyboard focus states use semantic roles while retaining real HTML select behavior. Older WebView2 falls back to its OS picker, with explicit text/background roles and `color-scheme`; OS-owned hover/highlight and native color-picker chrome cannot be fully styled with page CSS. App context menus, dialogs and delegated title tooltips use the same roles. Tooltips retain accessible descriptions/names, restore title fallbacks on dismissal and support Escape without consuming keyboard navigation.

Use 120ms (`--studio-motion-fast`) for small state changes and 200ms (`--studio-motion-standard`) for entering surfaces; durations and easings come from `tokens.css`, never literals. Large surfaces travelling into place use `--studio-easing-emphasized`. Things that land use a damped spring: `--studio-spring-snappy` (ζ .72, about 4% overshoot, 340ms) for toasts, update reminders and folder flaps, and `--studio-spring-bouncy` (ζ .5, about 16%, 610ms) for the mod card. Springs are sampled `linear()` step responses with overshoot-bezier fallbacks where `linear()` is unsupported; `AtelierMotion.ease` and `AtelierMotion.springMs` expose the same values to WAAPI. Dialogs fade/translate 4px; controls use color and border feedback without shape morphing. Cards and portraits stay still on hover and press. Local folder-flap motion and truthful loading/save/export feedback remain. Avoid delaying input and animating layout in the asset grid. At the user's updated request, the 3D viewer starts a compatible standing idle on repeat; Play, Pause and Rest pose remain available. The camera rotates only during a requested turntable capture. Both `prefers-reduced-motion: reduce` and Settings → Motion → Reduce motion select static interface presentation.

## Continuity and presentation preferences

`continuity.js` moves the replaced grid container 8px over 160ms, with reverse
direction for Back/parent navigation. Feature-detected View Transitions connect
folder names to breadcrumbs, portraits to the contextual hero banner and cards
to the material/curve/VFX editors. Logical close and requests do not wait for an
animation to finish. Unsupported engines use short CSS/WAAPI transitions; no
card layout or asset geometry is animated. Dialogs have a 120ms discrete exit
where supported, and context menus scale from the actual pointer/keyboard anchor.

The home roster reads existing catalogue metadata; it never scans containers,
imports an asset or refreshes the remote catalogue. Selecting a hero reveals its
costumes, with separate buttons to open the hero or a costume. Missing catalogue
art leaves folder browsing available. Skin banners use a uniquely matched
same-hero nameplate, with the hero's story art as fallback; category emblems and
asset glyphs use their category roles. Edited
cards and sidebar rows share a clipped-corner marker. Sidebar material mosaics
and curve sparklines read existing saved JSON only, with generic symbols on error.

Both roster rows use side arrows, disabled at their scroll limits, with keyboard
activation and reduced-motion support. Hero artwork backgrounds, costume icon
rings, banner washes and the Continue edge sample the strongest saturated hue
weighted by its coverage, falling back to a common colour for neutral artwork.
Names and counts keep theme text on a plain panel. Missing artwork retains the
normal surface. The Hood uses the
published 0011 avatar because its default 0010 asset is a blank silhouette.

High contrast, Blueprint and Comic ink extend the preset list. Comfortable keeps
the existing density; Compact reduces control and row padding. Preferences use
`atelier.motion` and `atelier.density`, remain local to the browser profile and
synchronize across its windows. **Hero and skin colours are decoration only.**
Never use them for buttons, toggles, focus outlines, selection states or body
text. The chosen theme owns those roles and Krackle status/ownership inks.
Decorative motion follows the active hero or costume through `--krackle-energy`;
missing artwork restores the theme accent. Result colours retain their meaning.
Legacy `atelier.adaptiveAccent` values no longer recolour theme roles.

Native launch colors are mirrored into `_webview/window-theme.json`, independently
of project/config data. The cache validates colors and resolves System against
the current OS at launch. The desktop bridge updates Windows dark title bars;
caption and caption-text colors additionally use Windows 11 DWM attributes where
supported. Other hosts retain their native chrome.

The viewport uses ACES filmic output and one offline, prefiltered Three.js r185
RoomEnvironment. A 420ms clipping plane sweeps from wireframe to shaded materials.
Display colour and dye-texture changes blend for 150ms in linear space; exact
project values stay unchanged. Fit and double-click framing ease for 260ms and
yield immediately to camera input. Hover uses a thin silhouette outline; click
selects a material and reveals its contextual inspector. Advanced parameters
contain the full material editor. The grid fades with distance and has a soft
grounding shadow; small camera axes orient the stage. Optional emissive bloom defaults off, caps three temporary
render targets at 512px per side, and releases them on disable or close. Flat
albedo and dye-region modes bypass bloom. Transparent captures retain alpha.
Reduced motion settles reveal, camera and colours immediately. Lighting,
comparison and capture never persist these display choices.

Custom material textures retain content-addressed project images under
`.atelier/custom_textures/`. Package location edits change only the material's
slot metadata: a `T_` name and folder in `/Game/Marvel/`, previewed in full before
saving. The default remains `Atelier/Custom/<material-slot-hash>/T_<name>`.
Explicit folders accept letters, numbers and underscores, up to 160 characters
total and 64 per segment. Traversal, drive/UNC paths, encoded separators,
Windows device names, Plugins and Marvel_LQ roots are refused. Names allow up to
60 characters after `T_`. Save and export reject case-insensitive collisions with
indexed game packages, existing project assets and every other custom slot.
Changing an image retains its chosen location; changing a location retains the
image. Failed validation keeps the previous assignment and editor input. Replies
are bound to their originating project and material editor.

Model Studio has its own blue/slate surface tokens, labelled header, broad stage,
contextual right inspector and bottom playback bar. Its main action is Save changes.
Model/part visibility and material-set choices live in Model; camera, lighting,
backdrop, wireframe, grid, dye regions and bloom live in View settings. Menus open
one at a time, close on outside click and consume Escape before the workspace closes.
Related materials share a readable group and expose a part picker only when needed.
No material is selected on open. Colour and hex inputs, Saved/Current swatches and
per-material restore appear after selection; exact shader parameters stay collapsed.
Progress, save results and warnings stay in the studio status bar. Opening a skin
shows one mesh; explicit choices can switch forms or combine mesh parts. Rig IDs
remain distinct when matching recolour material sets, and switching meshes resets
idle discovery/playback for the selected rig. Colour inputs invert the preview's
ACES curve so the chosen hex survives selection and save; untouched HDR values
and per-parameter saved restores keep their exact source floats.

Assembly is an optional, remembered workspace beside Inspect and Showcase. Its
geometry rail, central stage, texture shelf and material inspector form one
resizable layout. It inherits the application’s semantic palette roles. Preview
sections retain primitive and geometry-group identity; material and texture
relationships use complete package paths. Name-based or recolour counterparts
remain explicitly unverified. Derived eye shader defaults are identified and
excluded from connected texture slots. Material colours and full editors keep
their established save paths. Editor handoffs retain the scene, camera and
selected surface; model replacements refresh changed meshes and restore the
verified cooked material slot when available. Finite dotted links and selected
surface outlines reinforce relationships; reduced motion suppresses the links.
Texture cards lazily request 160px previews with two readers and a 48-image cache.
VFX inspection is explicit and limited to outgoing package references; no reverse
dependency discovery or filename-based effect association is claimed.

`polish.js` exposes disposable `mount`, `setState` and `destroy` handles through
`AtelierMotion.polish`. Toasts resolve on the same operation mount; repeated
ordinary notices merge with a counter and reset their hover-paused timer line.
Import segments and Activity rings reflect actual server outcomes/progress, and
the launch splash polls completed container reads rather than estimating time.
Save/import fly effects, sidebar row exits and export packing use inert snapshots
and never postpone the underlying action. The first successful export can show a
single brief burst sampled from the mod's selected previews; reduced motion uses
static color chips. Clicking the A mark explicitly replays its entrance. The
viewport loader samples the current artwork and lightens its accent for contrast.

### Krackle

Loading, saving and export use prominent formations: 112px in the model loader,
184px during import and 216px during export. Editor saves show a 44px charge beside
their status text (36px in Model Studio); result notifications use 40px. In Full,
the panel border itself carries a coordinated SVG charge: loading gathers into a
crest, saving presses a seal, and export packs then releases. Its curves and thickness match
the native border, with no floating overlay elements. It stops on completion,
failure, closure or lost visibility and restores the ordinary border. Background
panels, Calm and Off have no moving borders; overlapping operations share one frame.

Job feedback, ownership markers, empty states and occasional brand moments use **Krackle**, after Jack Kirby's krackle (credited here only; the product calls it Krackle). Solid ink defines each silhouette, with holes composed inside it. Loading and saving have an identifiable reservoir, a continuous fluid channel and a receiving seal. Actual panel borders carry that same ink; confirmed completion catches, compresses, rebounds and spreads along the receiving edge. Configuration discovery connects the panel edges through its scanner and latch. Activity's compact counted ring remains a job indicator. Success, warning and failure retain distinct settled silhouettes and adjacent text that carries their meaning.

- Every gesture has a source, a path and a receiving point. Imports connect the asset card frame to its Mod tray row; packing connects the selection to Export. A source reservoir visibly charges, then a thick, tapered SVG stream follows a measured curve. At arrival, the receiving ink compresses, rebounds once and spreads along its own border. Artwork and controls remain fixed. Missing or hidden sources skip the transfer. Local gestures stay in the owning surface's edge band, with filled seals and punched holes. Calm retains brief local pulses; Off stays static. Chrome keeps Material Sharp glyphs.
- Text, control glyphs, inputs, source previews, swatches and model canvases are cut out of decorative ink. At most three finite workflow gestures run; wide formations share the existing stage owner. Edge ink has four gestures, each with one meaning: **Arrive** (a hero, editor, panel, workspace, project or tray entry arrived), **Trace** (you moved; folder navigation follows its direction), **Seal** (you committed a pin, selection or primary action) and **Release** (you undid one; the seal's jaws unwind). Context menus keep only their pointer-origin scale and draw no edge ink. Loading gathers into a reservoir, saving presses a stamp, and export packs and releases; no unrelated particle scatter accompanies these actions.
- Keep edited artwork trustworthy: never texture a colour swatch, a dye preview or the material-inspection viewport. A comic viewport mode would be an explicit showcase mode.
- Compose, don't scatter: bubbles gather into deliberate dark masses on the shadow side, with clean energy elsewhere and a clear silhouette edge. Bubbles sit at least one dot step inside the shape, so thin bands such as the ring keep only a sparse centreline. Success is mostly clean; failure carries one substantial mass. Highlights are crisp Paper specks, never a soft glow.
- Outcome colours are fixed per measured surface (`--krackle-*` in `gui/motion/krackle.css`); bubbles use Ink, except Paper holes in light-surface success. Paper glints are not counted as inks. Semantic UI colours remain separate.
- Interruption: a real result replaces any animation immediately and its text and controls render at once; busy-after-busy continues rather than restarting; only busy loops; settled or hidden stages stop drawing. The large stage belongs to the dialog the user has open; other jobs report through toasts and Activity.
- Reduced motion (OS or Atelier's setting) shows the final pose of every state.

Artwork is generated by `scripts/krackle_art.py`; see the [motion README](gui/motion/README.md).

The Windows installer uses native scalable controls with paired Paper and Ink
artwork. Its A mark feeds one continuous channel into a Krackle seal. The wizard
follows the system light/dark appearance, keeps installation progress native,
and leaves installation, upgrade and data-preservation behavior unchanged.
`scripts/installer_art.py --check` verifies the deterministic high-resolution
plates and transparent header mark.

## Symbols and brand assets

[Material Symbols Sharp](https://developers.google.com/fonts/docs/material_symbols) use unfilled geometry for a precise, angular visual language. Compact controls use 24px optical artwork at weight 400; 41 large aliases use 48px optical artwork at weight 300 when requested at 32px or larger. This keeps large previews from becoming heavy, enlarged toolbar symbols. Folder glyph slots occupy 76% of their thumbnail; toolbar glyphs stay compact. The bundle has 103 aliases, preserving all 72 previous aliases, `data-lucide` markers and `lucide.createIcons` calls as a compatibility boundary. The production page loads the local Material adapter, not the old library. Glyph provenance for both sizes is recorded in `gui/vendor/material-symbols/sources.json`, pinned to Google repository commit `49d4db35df873165d6bd6ba09b063c7dafbac2f4`. Keep accessible names on buttons; decorative SVGs are hidden from assistive technology.

The A mark is drawn in Krackle. A rounded A of solid energy, wide-footed as before, has a round counter: the counter is the mark's largest bubble. One composed mass of bubbles gathers in the right foot, on the shadow side, and thins into satellites up the leg; the left leg and apex stay clean. Bubbles are true holes, so the surface shows through and the header's black/white filter keeps them. There are no outlines, gradients or glints: a Paper glint would read as one more hole on white and vanish under the filter. Small sizes are drawn rather than shrunk: 16–24px keeps only the counter, 32–64px (and the interface PNG) the two largest bubbles, and 128px and up the whole mass. The baseline and crossbar fall on whole pixels at 16, 32 and 48px. Outside the interface the energy keeps the clear blue `#5487db`.

The previous mark, an Image Gen raster, separated its strokes with a diagonal cut about 0.6px wide at 32px, so its one distinctive detail vanished in the header and taskbar, and its alpha edges carried cyan fringing. `scripts/brand_mark.py` now draws the mark from geometry and writes `gui/brand/atelier-mark.svg` (editable vector), `gui/brand/atelier-mark.png` (256px interface raster for the header, launch splash and favicon), `icon.ico` (a drawing per size, 16–256px) and `icon.png` (1024px, Linux desktop entry). Run it after any change; `--check` fails when a file is stale and runs with the logo browser checks. No new logo/font/icon runtime dependency is required.

Asset glyphs and the Sharp fallback use 22 `--studio-icon-*` roles: folder, character, UI,
texture, VFX, material, curve, mesh, text, nameplate, plugin, weapon, unknown,

Each family has its own color in both themes; folders, assets and home shortcuts

## Library shortcuts and preview feedback

Search is explicitly scoped to the current folder. It matches combined name,
hero/skin labels, IDs and full paths without case or accent sensitivity. Type
and edited/not-edited filters share the visible texture set used by Edit All.
The filter bar separates Type/Status from Sort/Size, with quiet native selects
and a visible fill for active filters. Clear filters appears only for an active
type/status filter or a This folder query. Clearing restores keyboard focus to
the relevant control and keeps the remembered sort and tile size.
Navigation clears transient search/filters. Recommended ordering, natural name
sorting, type sorting and edited-first sorting retain folders first; four card
widths (128, 156, 196 and 236px) resize previews with their cards. Sort and size
persist under `atelier.libraryView.v1`; storage failure keeps session behavior.

The grid supports arrows, Home/End, Enter, Backspace to the parent, and
Shift+F10 for its context menu. Alt+Left/Right traverses history; Alt+Up opens the
parent. Space/P or the small preview action opens texture/character artwork or
the existing 3D viewer without importing an asset. Escape closes image previews
and restores focus. Preview loading failures offer a retry. These shortcuts do
not replace normal edit actions or change export selection.

Every folder has a separate 26px pin button, shown on hover/keyboard focus and
always visible when pinned or using touch. The context menu offers the same
Pin/Unpin action. Home shows compact 32px shortcut chips above the grid; each
has an independent remove button, and its tooltip exposes the full folder path.
Original folder tiles and navigation remain available. Home search filters the
shortcuts as well as the grid; shortcut counts do not inflate the asset count.

Pins use versioned `atelier.homePins.v1` browser/WebView storage, independent of
project data and exports. They persist across reloads, synchronize across windows
in the same browser profile, and work for the current session if storage is blocked.
Browser and desktop profiles have separate pins, just as they have separate themes.
Previously saved generic pins resolve their current category from the final path
segment on load. The v1 storage shape, paths and pin ordering stay intact.
Nested pins use contextual labels such as `Storm · Goddess of Thunder · Textures`.
Resolved labels omit redundant numeric prefixes; full paths remain in tooltips.
Unknown ancestors retain their path segments until display labels are available.

Loading previews show the Krackle 45° dot screen, breathing in opacity on two beats (still in
Calm, Off and reduced motion), instead of a generic shimmer. File glyphs (meshes, textures and
other assets) sit on a rounded tonal plate in their family colour, which gives the thin Sharp
outlines the visual weight of the filled folder emblems while still marking them as files.
"Preview unavailable" sits on its own solid chip so it stays legible over the checkerboard.

Texture tiles request cached previews on every grid build, including search.
Missed background completion events recover through status polling. Failed or
timed-out requests show a texture glyph and `Preview unavailable`; the context
menu offers `Retry preview`. Grid replacement cancels polling and ignores late
responses. The preview pipeline does not import assets or select them for export.

## Material and export workflows

Material parameters are grouped into surface colors, dye regions and scalars.
Per-row markers, the title and a live count distinguish unsaved parameters.
Comparison switches between the last saved project values and read-only original
game values; unavailable original data is reported instead of borrowing the saved
baseline. `Use value` changes only the draft. `Revert unsaved` restores the saved
baseline; resetting to game defaults remains a separate persistence action.
Partial saves and edits made during a save retain the remaining draft. The 3D
editor provides saved-color comparison swatches and an explicit unsaved count.

Export first reviews included names/types/paths, exclusions and reasons, project,
destination and protection state; passwords are never displayed. Confirmation,
overwrite and retry revalidate the captured project, selection and settings.
Unsaved material/viewport drafts and in-flight saves return focus to the relevant
editor without discarding changes. The build remains indeterminate because the
existing endpoint reports completion rather than a measured progress percentage.
Its window can be hidden and reopened. The latest result stays available for the
session, with full applied/skipped details, output paths, reveal, Settings and
manual retry. A built mod whose copy failed is distinct from a failed build.
Retry checks existing output again; there is no automatic build retry.

The comparison endpoint is read-only. Existing save/export payloads, project
headers, project sidecars and mod container formats remain compatible.

## Character and skin artwork

Names and numeric IDs come from [donutman07/MarvelRivalsCharacterIDs](https://github.com/donutman07/MarvelRivalsCharacterIDs); artwork and costume-page IDs come from [RivalSkins](https://rivalskins.com/heroes/). Settings links to both sources. Marvel Rivals artwork belongs to its respective owners; the bundled seed contains metadata and source links, not the remote artwork binaries.

Matching uses costume-page numeric game IDs first. When a recolor page omits an ID, only a unique normalized exact name within the same hero is accepted. No fuzzy matching is used. Conflicting IDs, ambiguous names and NPCs sharing a playable hero's name are not silently assigned unrelated skin art. Missing skin art uses a labelled hero portrait; unavailable heroes use the folder symbol. Default skin IDs are not invented.

The current seed contains 820 entries, with 700 matched costumes (564 by source ID,
136 by exact name), 459 matched costume nameplates and 54 hero nameplates, each
paired with its square icon. All 54 heroes with published portraits have a
verified nameplate: 44 plain plates and 10 Immortal fallbacks. Seven
named skins use hero fallbacks. Unknown skin folders can also fall back to their
known hero. These counts describe the seed snapshot, not future source coverage.

Nameplates are paired only when normalized names match exactly and uniquely on
both sides of one hero page. Costume art fallbacks never inherit a nameplate.
The library header prefers the costume's exact nameplate, then the hero's own
nameplate. Hero plates match the roster's name exactly on that hero's page; when
the plain plate is absent, the unique `Immortal <hero name>` plate is used. No
unrelated costume plate is borrowed. Model Studio uses the same order above its
Materials list. Story artwork is the final fallback when no plate is available.
The strip fills the container to its sides and the controls below. Artwork
occupies the right side with a modest bleed past its slanted edge. The text
surface fades out before the character, keeping the image's colour and contrast.
The title uses the costume icon, then the matched square nameplate badge, then
the hero avatar. Wide nameplate reads request lazy 4× sharpening at every display
scale. Story reads queue the requested hero instead of sharpening the whole roster
